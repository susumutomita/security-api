## ヘルスチェックスコア（確定）

プラットフォームは **60秒間隔（1分ごと）** で各チームの Website と API Flask App のヘルスチェックを行う。

| 条件 | ポイント |
|------|---------|
| Website + API **両方UP** | **+100pt / チェック** |
| どちらかDOWN | **-100pt / チェック** |

- プレーヤー間の攻撃は **ゲーム開始時から可能**（明確なフェーズ切替は存在しない）
- 運営がゲーム途中で **手動妨害を注入** する（パスワードローテーション、S3サイト書き換え等）
- 妨害によりサイトがダウンした場合、復旧が遅れるほど **-100pt/分** が蓄積する
- チームはURLを変更した場合、新しいURLをプラットフォームに提出できる

## スコア重みの運営制御

運営は裏側で **ダウンタイムペナルティの重み** を変更できる。

| スコア重み | ダウンタイムペナルティ | 切替方法 |
|-----------|---------------------|---------|
| 通常 | -100pt / チェック | デフォルト |
| 高ペナルティ | -1,000pt / チェック | 運営が手動で切替 |

- 切替時、運営からプレーヤーに **「-1,000になりました」とアナウンス** される（確定）
- 切替タイミングは運営が任意に決定（確定）

## DR要件

- **RTO（目標復旧時間）**: 10分
- **RPO（目標復旧時点）**: 5分
- RTOを超えたダウンタイムが続くほどペナルティが増加する（PROMPT.mdの記述）

- RTO は独立した仕組みではなく、**運営が設定したスコア重み（-100 or -1,000）がそのまま適用** される（確定）
- つまり RTO 超過自体でペナルティが自動エスカレートすることはない

## 倹約ポイント（確定）

EC2インスタンスが **1台に最適化** されている場合、ヘルスチェックのたびに **+100pt** のボーナスが付与される。

| 条件 | ポイント | タイミング |
|------|---------|-----------|
| EC2インスタンス = 1台 | **+100pt** | 60秒ごとのチェック時 |

つまり、サイトUP (+100pt) + インスタンス最適化 (+100pt) = **毎チェック最大+200pt** が獲得できる。

## 攻撃ポイント（確定）

全攻撃で共通の値:

| 結果 | 攻撃者 | 被害者 |
|------|--------|--------|
| 攻撃成功 | **+1,000pt** | **-1,000pt** |
| 攻撃ブロック（脆弱性修正済み） | 0pt | **+1,000pt**（ブロックボーナス） |

- 購入コスト: **3,000pt**（全攻撃共通、一度きり）
- クールダウン: **5分**（全攻撃共通）
- 購入前に「与えるダメージ」と「成功時の報酬ポイント」を確認できる
